# novel-forge

ジャンルとタイトルを入力するだけで、キャラクターシート・プロット・本文を自動生成するローカルLLM小説執筆システム。

LM Studio（またはOpenAI互換エンドポイント）経由でローカルLLMを使用します。

---

## 特徴

- **3段階の長さ対応**：ショートショート・短編・中編を選択可能
- **台帳ベースの整合性管理**：要約せず事実を記録し、シーンをまたいだ矛盾を自動検出
- **段階的プロット設計**：幕→章→シーンの順に詳細化し、書き進めながら再計画
- **narrative-interactとの設計的連続性**：プロット生成・ビート管理・2層プロンプトの知見を継承

---

## 使い方

```bash
# 通常起動
python main.py

# デバッグモード（リクエスト/レスポンスをdebug/に記録）
python main.py --debug

# セーブデータから再開
python main.py --load saves/<title>_<scene_no>.json
```

起動後、ジャンル・タイトル・長さを入力するとシステムが自動で以下を行います：

1. キャラクターシートの自動生成
2. プロット構築（幕→章→シーン）
3. 本文の順次生成
4. シーンごとの整合性チェック

---

## 必要環境

- Python 3.10+
- LM Studio（推奨モデル：Gemma4 12B）
- 依存ライブラリ：`pip install -r requirements.txt`

---

## 長さの目安

Gemma4 12B での動作実績に基づく現実的な規模感です。

| 種別 | 目標文字数 | シーン数 |
|------|-----------|---------|
| ショートショート | 〜6,000字 | 3シーン |
| 短編 | 〜1.5万字 | 12シーン前後 |
| 中編 | 〜3万字 | 25シーン前後 |

> 長編（10万字〜）は12Bモデルでは整合性維持が困難なため非対応。32B以上のモデルを推奨。

## ディレクトリ構成

```
novel-forge/
├── main.py          # エントリポイント
├── config.py        # LM Studio接続設定
├── api.py           # LLM API呼び出し
├── state.py         # セッション状態管理
├── plot.py          # プロット生成
├── character.py     # キャラクターシート生成・状態更新
├── scene.py         # シーン生成・本文出力
├── ledger.py        # 台帳（整合性管理）
├── verify.py        # 矛盾検出・検証
├── prompt.py        # システムプロンプト群
├── save.py          # セーブ/ロード
├── display.py       # 表示ユーティリティ
├── output/          # 生成された本文（.txt）
├── ledger/          # 台帳データ（.json / SQLite）
└── debug/           # デバッグログ
```
